## 改进措施（9/3 实施）

### 对场景 3 的诊断

远处视觉误差远大于 MT1 输出的 `stdDev`，而旧实现存在两个缺陷：

1. **R 上界截断**：`mapStdToR` 在 `STD_HIGH` 处把 R 截断在 `0.01 × R_MAX_SCALE`，因此距离再远、stdDev 再大，视觉观测噪声也不会继续增长，滤波器仍然过度信任远处的视觉解。
2. **无离群点拒绝**：失真的视觉解直接被当作有效观测更新，单个误观测即可把位姿带偏。

### 具体改进（所有定位器共用的视觉 R 逻辑）

1. **去除 R 上界**：`mapStdToR` 改为无上界线性映射，`std > STD_HIGH` 后继续线性放大，不再封顶。
2. **距离二次缩放**：位置方向的 R 额外乘以 `distFactor = (dist / DIST_REF_M)²`（`dist > DIST_REF_M` 时），体现视觉位置误差随距离近似二次增长。
3. **标签数缩放**：位置方向的 R 额外乘以 `tagFactor = TAG_REF / tags`（标签 `< TAG_REF` 时，上限 `TAG_SCALE_MAX`），标签越少解算越不可靠。
4. **马氏距离门控**：视觉更新前先 `gateVision()` 计算 `d² = innovᵀ·S⁻¹·innov`，仅当 `d² ≤ GATE_THRESHOLD²` 才接受本次更新，其余作废（predict 照常，依赖里程计直到下一次可信观测）。

详见 [Theory.md](./Theory.md) §5.3–5.5、[Theory5D.md](./Theory5D.md) §6.4、[Params.md](./Params.md) 顶部「视觉 R 自适应与马氏门控」。

### 待验证

- 远离 tag 时位姿应不再被视觉带偏，视觉恢复后仅做缓慢修正。
- 场景 1（MT1 偶尔无数据）暂未改动，需进一步区分是遮挡、曝光还是算力/帧率问题。

# 9/3

在 into the deep 不完整场地运行FusionTestOpMode

## 1.视觉无效/撞击

pinpoint发生小偏移，其余定位器在视觉恢复后恢复正常

## 2.视觉有效/远离tag

大的定位误差被拒绝，所有定位器均正常

## 3.pinpoint失效/远离tag

将车搬离地面并移动一段距离，随后在远离tag的位置短暂恢复视觉，观察到

- pinpoint：完全失效
- EKF/UKF：收敛缓慢，视觉再次失效前未能完全定位准确
- **AdaptiveEKF/UKF：积累了极大的Q，收敛极快，定位准确**
